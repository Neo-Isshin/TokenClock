# Glass：本机 Codex 检测入口

本轮接入本地执行路径，不更改 Ailyre 线上判断规则或 MC-20261024-r1 冻结基线。没有真实模型生成、新采样或模型费用。

## 用户路径

Model Detect → 本机 Codex → 选择型号 → 开始检测。自动读取 TokenClock 配置的 Codex 目录，优先使用桌面应用随包的 Codex，复用其登录与服务配置。识别出的 Codex 会话页也提供“用本机 Codex 新建测试”；不会继续或复制原会话。

读取配置和型号列表不发题。默认使用当前配置中且仍在目录内的型号；此前选定型号失效时清空选择，不换成其他型号。点击开始前显示题数及账户额度说明，点击后先核对范围再提交。型号目录不是权限保证，实际权限错误会保留并停止。

默认三道既有数字题；折叠设置中可选既有 O05:A / O06:A / O07:A，各重复两次。题面保持冻结原文。每份回答使用新的 ephemeral thread，严格串行。请求指定型号、来源及推理档位；不允许客户端型号回退，核对创建回执后才发题。不调用模型评审。

## 保留条件差异

使用独立空目录，不带旧聊天、答案或反馈。关闭可配置的工具、插件、记忆、hooks 与技能，并记录覆盖项。真实客户端的无生成检查发现：即使文档长度设置为零，仍可能报告全局 AGENTS.md，因此不声称完全移除了个人指令，也不修改用户的 AGENTS.md、配置或登录文件。

当前本地入口保存回答、可见型号声明、thread/turn ID、事件类型与时间、结束原因、用量及缺失字段。响应模型、上游请求 ID、路由、费用不可见时保留 null；创建会话返回的型号单列为 resolved_model，不冒充上游响应型号。

数字算法可对有效回答做离线参考比较，结果仅留在详情；行为题做既有特征提取。由于本地指令环境没有同条件验证，主卡片显示“暂不能确认型号”，不输出身份概率，不把 API 参考阈值迁移过来。要改变这项判定，仍须先离线比较、由用户审阅决定。

## 运行边界和保存

- 3 或 6 个测试回合，不自动重发题目、不自动续跑；读取结果不重新评分。
- 整轮 900 秒、每题 300 秒、无可见生成进展 120 秒时停止。仅用量/心跳变化不算答题进展；可见推理事件算进展，但不保存其私有推理内容。
- 65,536 个已观测总 token 为停止阈值；app-server 没有每回合硬输出上限，此阈值不能保证服务端绝不超出，也不是美元预算保证。单条协议消息/回答保留有 4 MiB 边界。
- TokenClock 不重试；Codex 自身的底层网络重试可能不可见。测试回合数不冒充服务端实际请求次数。
- 额度来自所选 Codex 账户（订阅或 API），美元费用未知，不当作免费。
- 取消、中断、未知提交结果均保留已有记录；没有取到 turn ID 的提交尝试仍计入尝试数。停止后使用现有详情里的证据保存入口，不创建新会话。
- Key/OAuth 由 Codex 管理。TokenClock 不提取、复制或上传凭据，任意原始配置不写入检测记录。

## 验证与交付

- 58 项 Python 检查通过（14 项新入口检查 + 44 项既有数字题、连接、预览和流程检查）。
- 原生离线状态检查通过：读取目录不生成、无需 Key、无候选不开始、预览题数不一致不提交、一次点击仅提交一次、不带源会话、结果不冒充明确判断。
- 打包工作进程：使用合成 Codex 子进程完成三题/三个独立会话、离线计算、报告和 ZIP 导出；中途取消后部分证据可导出。没有访问模型服务。
- 真实本机仅核对账户/目录及空临时会话的创建：型号、来源、low 档位、ephemeral 均可返回；没有调用 turn/start。
- Glass Release 编译成功。系统默认 macOS 27 SDK 缺少 SwiftUI 宏插件，使用现有 26.5 SDK 构建。既有 StatusSummaryView 中两条长文字表达式提取为等价 String 变量以兼容本机编译器，显示及行为不变。
- 本机缺少完整 Xcode 的 XCTest 框架，因此完整 swift test 未运行成功；新增 XCTest 用例已保留，另用实际原生模块的独立 smoke 程序验证。
- 验收版独立打包、开发签名；未覆盖正在使用的 Glass、未公开发布、未同步其他版本。原生窗口实机目检暂因 Mac 锁屏而待办。

交付目录：`output/local-codex-20261028/`。应用：`TokenClock Glass Local.app`。检查回执、模拟报告和测试日志在 `checks/`。此包用于本轮验收，不是新的冻结回归基线。
